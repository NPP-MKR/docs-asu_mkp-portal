# Установлення порталу АСУ МКР

Версія документа: 1.0

## 1. Вступ

Цей посібник описує встановлення нової копії порталу **АСУ МКР**.

Основною рекомендованою платформою є Linux. Портал також можна розгорнути на Windows Server, однак окрема інструкція з підготовки Windows у цій документації не надається.

Дії наведено в тому порядку, у якому їх необхідно виконувати.

!!! warning "Важливо"
    Не переходьте до наступного етапу, доки попередній не завершено та не перевірено.

## 3. Системні вимоги

### Операційні системи

| Операційна система | Версія |
|---|---|
| Ubuntu Server | 22.04 LTS і вище |
| Debian | 12 і вище |
| Windows Server | Підтримується без окремої інструкції |

### Програмне забезпечення

| Компонент | Вимога                         |
|---|--------------------------------|
| PHP | 8.2 і вище, рекомендовано 8.3 |
| Composer | 2.6 і вище                     |
| Git | актуальна стабільна версія     |
| Firebird | 3.0.x                          |
| Вебсервер | Apache або Nginx               |

### Розширення PHP

`bcmath`, `curl`, `dom`, `fileinfo`, `gd`, `gettext`, `iconv`, `imap`, `intl`, `mbstring`, `openssl`, `pdo`, `pdo_firebird`, `simplexml`, `xml`, `zip`.

### Апаратні вимоги

| Параметр | Мінімум (пілот) | Рекомендація (середній виш) |
|---|---|---|
| CPU | 4 vCPU (2 GHz+) | 8 vCPU (2.5 GHz+) |
| RAM | 8 ГБ | 16–32 ГБ |
| Диск (SSD) | 100 ГБ | 250–500 ГБ (NVMe) |
| Мережа | 100 Мбіт | 1 Гбіт |

!!! note "Примітка"
    Наведені значення є оціночними для середнього вишу (5–15 тис. користувачів). Для пілотного стенду допустимі мінімальні параметри. Точні вимоги визначаються навантажувальним тестуванням.

При необхідності виділення окремого сервера Firebird:

| Роль | CPU | RAM | Диск |
|---|---|---|---|
| Вебсервер (nginx + PHP-FPM) | 4–8 vCPU | 8–16 ГБ | SSD 100 ГБ |
| Firebird (БД) | 4–8 vCPU | 8–16 ГБ | SSD 250+ ГБ |

### Дисковий простір

| Компонент | Розмір (приблизно) |
|---|---|
| Вихідний код проєкту | ~30 МБ |
| Vendor (Composer) | ~230 МБ |
| Assets (JS/CSS) | ~16 МБ |
| `storage/` (файли користувачів) | зростає (10–100+ ГБ) |
| `runtime/` (кеш, журнали, сесії) | 1–5 ГБ |
| Резервні копії Firebird | 1–2 розміру БД |

!!! note "Примітка"
    Рекомендується виділити окремий диск або розділ для `storage/` та окремий — для резервних копій Firebird.

### Рекомендовані параметри PHP

!!! warning "Важливо"
    Наведені значення є рекомендованими. Конкретні параметри визначаються навантаженням та вимогами організації.

```ini
memory_limit = 512M
upload_max_filesize = 64M
post_max_size = 64M
max_execution_time = 120
date.timezone = Europe/Kyiv
realpath_cache_size = 4096K
realpath_cache_ttl = 600
```

!!! note "Примітка"
    `realpath_cache_size` та `realpath_cache_ttl` кешують результати розв'язання шляхів файлів. Yii2 активно використовує `realpath()` через автозавантаження та аіаси — ці параметри зменшують кількість `stat`-викликів до файлової системи.

Докладна інструкція з налаштування PHP наведена в документі `server-linux.md` (розділ 7).

### Налаштування OPcache (продакшн)

!!! warning "Важливо"
    OPcache суттєво прискорює виконання PHP-застосунку, кешуючи скомпільований байт-код. Рекомендується увімкнути на всіх продакшн-серверах.

Визначте розташування конфігураційного файлу OPcache:

```bash
php --ini
```

Налаштування OPcache можна додати в основний `php.ini` або в окремий файл (наприклад, `/etc/php/8.3/mods-available/opcache.ini`).

Рекомендовані параметри:

```ini
opcache.enable = 1
opcache.memory_consumption = 128
opcache.interned_strings_buffer = 16
opcache.max_accelerated_files = 10000
opcache.validate_timestamps = 0
opcache.revalidate_freq = 0
opcache.save_comments = 1
opcache.enable_file_override = 0
```

| Параметр | Значення | Опис |
|---|---|---|
| `opcache.enable` | `1` | Увімкнути OPcache |
| `opcache.memory_consumption` | `128` | Пам'ять для кешу (МБ). Для великих проєктів можна збільшити до 256 |
| `opcache.interned_strings_buffer` | `16` | Пам'ять для інтернованих рядків (МБ) |
| `opcache.max_accelerated_files` | `10000` | Максимальна кількість файлів у кеші |
| `opcache.validate_timestamps` | `0` | Не перевіряти час зміни файлів (prod). При оновленні коду — виконувати `opcache_reset()` або перезапуск PHP-FPM |
| `opcache.revalidate_freq` | `0` | Частота перевірки (актуально при `validate_timestamps=1`) |
| `opcache.save_comments` | `1` | Зберігати PHPDoc-коментарі (необхідно для фреймворків) |
| `opcache.enable_file_override` | `0` | Не перевизначати `opcache.enable` на рівні файлів |

!!! warning "Важливо"
    При оновленні порталу через `git pull` + `composer update` **обов'язково** очищайте OPcache:

    ```bash
    # Перезапуск PHP-FPM (рекомендується)
    sudo systemctl restart php8.3-fpm

    # Або через CLI
    php yii cache/flush-all
    ```

    Без очищення кешу зміни у PHP-файлах не набудуть чинності до перезапуску PHP-FPM.

### Безпека та мережа

| Вимога | Коментар |
|---|---|
| HTTPS | Обов'язковий для Frontend, Backend та API |
| Порт Firebird | 3050 — лише для сервера порталу, не публікувати в Інтернеті |
| Часовий пояс | `Europe/Kyiv` |
| Бекапи Firebird | Щоденне резервне копіювання (`gbak`), зберігання 7–30 днів |
| Міжмережевий екран | Закрити всі порти окрім 80, 443; SSH лише для адміністратора |
| Права доступу | Власник — користувач вебсервера, каталоги `0775`, конфіги `0664` |

### Чек-лист перед запуском

#### Програмне забезпечення

- [ ] PHP ≥ 8.2 встановлено
- [ ] Усі обов'язкові розширення PHP завантажені (`php -m`)
- [ ] Composer ≥ 2.6 встановлено
- [ ] Git встановлено
- [ ] Firebird 3.0.x встановлено та запущено
- [ ] Вебсервер налаштовано з rewrite rules

#### Конфігурація

- [ ] `memory_limit` ≥ 512M
- [ ] `upload_max_filesize` ≥ 64M
- [ ] `post_max_size` ≥ 64M
- [ ] `date.timezone` = `Europe/Kyiv`
- [ ] Залежності Composer встановлено (`composer install --no-dev`)

#### База даних

- [ ] Firebird доступний на порту 3050
- [ ] Підключення через `PDO_Firebird` працює
- [ ] Кодування з'єднання: `charset=UTF8`
- [ ] Резервне копіювання налаштовано та протестовано

#### Файлова система

- [ ] Каталоги `runtime/` доступні для запису
- [ ] Каталог `storage/` доступний для запису
- [ ] Права: власник — користувач вебсервера

#### Мережа та безпека

- [ ] HTTPS працює (порт 443)
- [ ] Порт 3050 закритий від зовнішнього доступу
- [ ] Міжмережевий екран налаштовано

#### Застосунок

- [ ] Сторінка входу завантажується
- [ ] Авторизація працює
- [ ] API відповідає

## 4. Підготовка сервера

Спочатку встановіть і початково налаштуйте операційну систему.

Потім послідовно встановіть:

1. PHP та обов'язкові розширення.
2. Composer.
3. Git.
4. Firebird 3.0.x.
5. Apache або Nginx.

Докладна інструкція для Linux наведена в документі [Підготовка сервера Linux](server-linux.md).

## 5. Отримання вихідного коду

Після підготовки сервера налаштуйте SSH-доступ і клонуйте потрібну версію порталу відповідно до документа [Отримання вихідного коду](repository.md).

Після клонування запам'ятайте повний шлях до каталогу проєкту, наприклад:

```text
/var/www/mkp
```

У документації цей шлях позначається як:

```text
<каталог_порталу>
```

## 6. Установлення залежностей

Перейдіть до каталогу порталу:

```bash
cd <каталог_порталу>
```

Установіть PHP-залежності без пакетів для розроблення:

```bash
composer install --no-dev
```

!!! warning "Важливо"
    Команда має завершитися без критичних помилок.

## 7. Ініціалізація проєкту

У кореневому каталозі порталу виконайте:

```bash
php init --env=Production
```

Під час ініціалізації створюються локальні конфігураційні файли, каталоги, посилання та необхідні права доступу.

!!! warning "Важливо"
    Команда `php init --env=Production` виконується лише під час початкового встановлення. Під час оновлення її запускати не потрібно.

Після завершення відкрийте файл:

```text
common/config/main-local.php
```

У ньому виконується початкове налаштування порталу.

### 7.1 Права доступу

Після ініціалізації перевірте права доступу до робочих каталогів і конфігураційних файлів порталу.

| Каталог | Призначення |
|---|---|
| `backend/runtime` | runtime backend |
| `backend/web/assets` | assets backend |
| `frontend/runtime` | runtime frontend |
| `frontend/web/assets` | assets frontend |
| `api/runtime` | runtime api |
| `common/config/*-local.php` | налаштування порталу |
| `common/config` | конфіг-файли (languages, main, api-*, auth-local) |
| `frontend/config` | конфіг-файли (serviceManager-local.php) |
| `assets/users` | файли налаштування, logo, тексти на головній, portal.css/js та інші |
| `assets/contract` | файли шаблонів контрактів і статусів |
| `storage` | файлове сховище |

!!! warning "Права доступу"
    - каталоги — `0775`;
    - конфігураційні файли — `0664`;
    - власник — користувач веб-сервера.

## 8. Налаштування порталу

### Бази даних

У `common/config/main-local.php` налаштуйте два підключення Firebird:

| Підключення | Призначення |
|---|---|
| `BD` | Основна база даних АСУ МКР |
| `BDD` | Додаткова база даних |

Для кожного підключення вкажіть шлях або адресу сервера, ім'я користувача та пароль.

Докладно: [Налаштування Firebird](../configuration/firebird.md).

### Файлове сховище

За замовчуванням використовується локальна файлова система:

| Сховище | Каталог |
|---|---|
| `fs` | `@webroot/documents` |
| `storage` | `@frontend/web` |

Також підтримуються AWS S3, S3-compatible, FTP, SFTP і WebDAV.

Докладно: [Файлове сховище](../configuration/storage.md).

## 9. Налаштування вебсервера

Створіть три окремі віртуальні хости:

| Піддомен | Призначення | Кореневий каталог |
|---|---|---|
| `portal.example.com` | Користувацький портал | `<каталог_порталу>/frontend/web` |
| `admin.example.com` | Адміністративна частина | `<каталог_порталу>/backend/web` |
| `api.example.com` | API порталу | `<каталог_порталу>/api/web` |

Замість `example.com` використовуйте домен організації.

Докладно:

- [Apache](../web-server/apache.md);
- [Nginx](../web-server/nginx.md).

## 10. Налаштування HTTPS

HTTPS є обов'язковим для Frontend, Backend і API.

Для кожного доменного імені встановіть чинний SSL-сертифікат. Можна використовувати Let's Encrypt або сертифікат комерційного центру сертифікації.

HTTP рекомендовано залишити лише для перенаправлення на HTTPS.

Докладно: [Налаштування HTTPS](../web-server/ssl.md).

## 11. Перший запуск

Відкрийте в браузері:

```text
https://portal.example.com
https://admin.example.com
https://api.example.com
```

Переконайтеся, що:

- сторінки відкриваються через HTTPS;
- вебсервер не повертає помилок;
- портал підключається до `BD` і `BDD`;
- у журналах немає критичних помилок.

## 12. Оновлення порталу

Перед оновленням створіть резервні копії баз даних, `common/config/main-local.php`, документів і файлового сховища.

Перейдіть до каталогу порталу:

```bash
cd <каталог_порталу>
```

Отримайте зміни:

```bash
git pull
```

Оновіть залежності:

```bash
composer update --no-dev
```

Очистіть кеш застосунку:

```bash
php yii cache/flush-all
```

!!! warning "Важливо"
    Під час оновлення не запускайте `php init --env=Production`.

Після оновлення очистіть кеш браузера та повторно перевірте Frontend, Backend і API.
