# Установлення порталу АСУ МКР

Версія документа: 1.0

## 1. Вступ

Цей посібник описує встановлення нової копії порталу **АСУ МКР**.

Основною рекомендованою платформою є Linux. Портал також можна розгорнути на Windows Server, однак окрема інструкція з підготовки Windows у цій документації не надається.

Дії наведено в тому порядку, у якому їх необхідно виконувати.

!!! warning "Важливо"
    Не переходьте до наступного етапу, доки попередній не завершено та не перевірено.

## 3. Системні вимоги

### Операційні системи

| Операційна система | Версія |
|---|---|
| Ubuntu Server | 22.04 LTS і вище |
| Debian | 12 і вище |
| Windows Server | Підтримується без окремої інструкції |

### Програмне забезпечення

| Компонент | Вимога |
|---|---|
| PHP | 8.1 і вище, рекомендовано 8.3 |
| Composer | 2.6 і вище |
| Git | актуальна стабільна версія |
| Firebird | 3.0.x |
| Вебсервер | Apache або Nginx |

### Розширення PHP

`bcmath`, `curl`, `dom`, `fileinfo`, `gd`, `gettext`, `iconv`, `imap`, `intl`, `mbstring`, `openssl`, `pdo`, `pdo_firebird`, `simplexml`, `xml`, `zip`.

## 4. Підготовка сервера

Спочатку встановіть і початково налаштуйте операційну систему.

Потім послідовно встановіть:

1. PHP та обов'язкові розширення.
2. Composer.
3. Git.
4. Firebird 3.0.x.
5. Apache або Nginx.

Докладна інструкція для Linux наведена в документі [Підготовка сервера Linux](server-linux.md).

## 5. Отримання вихідного коду

Після підготовки сервера налаштуйте SSH-доступ і клонуйте потрібну версію порталу відповідно до документа [Отримання вихідного коду](repository.md).

Після клонування запам'ятайте повний шлях до каталогу проєкту, наприклад:

```text
/var/www/mkp
```

У документації цей шлях позначається як:

```text
<каталог_порталу>
```

## 6. Установлення залежностей

Перейдіть до каталогу порталу:

```bash
cd <каталог_порталу>
```

Установіть PHP-залежності без пакетів для розроблення:

```bash
composer install --no-dev
```

!!! warning "Важливо"
    Команда має завершитися без критичних помилок.

## 7. Ініціалізація проєкту

У кореневому каталозі порталу виконайте:

```bash
php init --env=Production
```

Під час ініціалізації створюються локальні конфігураційні файли, каталоги, посилання та необхідні права доступу.

!!! warning "Важливо"
    Команда `php init --env=Production` виконується лише під час початкового встановлення. Під час оновлення її запускати не потрібно.

Після завершення відкрийте файл:

```text
common/config/main-local.php
```

У ньому виконується початкове налаштування порталу.

### 7.1 Права доступу

Після ініціалізації перевірте права доступу до робочих каталогів і конфігураційних файлів порталу.

| Каталог | Призначення |
|---|---|
| `backend/runtime` | runtime backend |
| `backend/web/assets` | assets backend |
| `frontend/runtime` | runtime frontend |
| `frontend/web/assets` | assets frontend |
| `api/runtime` | runtime api |
| `common/config/*-local.php` | налаштування порталу |
| `common/config` | конфіг-файли (languages, main, api-*, auth-local) |
| `frontend/config` | конфіг-файли (serviceManager-local.php) |
| `assets/users` | файли налаштування, logo, тексти на головній, portal.css/js та інші |
| `assets/contract` | файли шаблонів контрактів і статусів |
| `storage` | файлове сховище |

!!! warning "Права доступу"
    - каталоги — `0775`;
    - конфігураційні файли — `0664`;
    - власник — користувач веб-сервера.

## 8. Налаштування порталу

### Бази даних

У `common/config/main-local.php` налаштуйте два підключення Firebird:

| Підключення | Призначення |
|---|---|
| `BD` | Основна база даних АСУ МКР |
| `BDD` | Додаткова база даних |

Для кожного підключення вкажіть шлях або адресу сервера, ім'я користувача та пароль.

Докладно: [Налаштування Firebird](../configuration/firebird.md).

### Файлове сховище

За замовчуванням використовується локальна файлова система:

| Сховище | Каталог |
|---|---|
| `fs` | `@webroot/documents` |
| `storage` | `@frontend/web` |

Також підтримуються AWS S3, S3-compatible, FTP, SFTP і WebDAV.

Докладно: [Файлове сховище](../configuration/storage.md).

## 9. Налаштування вебсервера

Створіть три окремі віртуальні хости:

| Піддомен | Призначення | Кореневий каталог |
|---|---|---|
| `portal.example.com` | Користувацький портал | `<каталог_порталу>/frontend/web` |
| `admin.example.com` | Адміністративна частина | `<каталог_порталу>/backend/web` |
| `api.example.com` | API порталу | `<каталог_порталу>/api/web` |

Замість `example.com` використовуйте домен організації.

Докладно:

- [Apache](../web-server/apache.md);
- [Nginx](../web-server/nginx.md).

## 10. Налаштування HTTPS

HTTPS є обов'язковим для Frontend, Backend і API.

Для кожного доменного імені встановіть чинний SSL-сертифікат. Можна використовувати Let's Encrypt або сертифікат комерційного центру сертифікації.

HTTP рекомендовано залишити лише для перенаправлення на HTTPS.

Докладно: [Налаштування HTTPS](../web-server/ssl.md).

## 11. Перший запуск

Відкрийте в браузері:

```text
https://portal.example.com
https://admin.example.com
https://api.example.com
```

Переконайтеся, що:

- сторінки відкриваються через HTTPS;
- вебсервер не повертає помилок;
- портал підключається до `BD` і `BDD`;
- у журналах немає критичних помилок.

## 12. Оновлення порталу

Перед оновленням створіть резервні копії баз даних, `common/config/main-local.php`, документів і файлового сховища.

Перейдіть до каталогу порталу:

```bash
cd <каталог_порталу>
```

Отримайте зміни:

```bash
git pull
```

Оновіть залежності:

```bash
composer update --no-dev
```

Очистіть кеш застосунку:

```bash
php yii cache/flush-all
```

!!! warning "Важливо"
    Під час оновлення не запускайте `php init --env=Production`.

Після оновлення очистіть кеш браузера та повторно перевірте Frontend, Backend і API.
