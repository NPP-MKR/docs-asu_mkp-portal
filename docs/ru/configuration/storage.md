# Настройка файлового хранилища

Версия документа: 1.0

## 1. Назначение

Документ описывает варианты хранения файлов портала АСУ МКР.

По умолчанию используется локальная файловая система.

## 2. Настройки по умолчанию

| Хранилище | Каталог |
|---|---|
| `fs` | `@webroot/documents` |
| `storage` | `@frontend/web` |

Для стандартной установки рекомендуется сначала использовать локальное хранилище и убедиться в корректной работе портала.

## 3. Локальная файловая система

Локальное хранилище подходит, если:

- портал работает на одном сервере;
- объем документов соответствует доступному дисковому пространству;
- настроено регулярное резервное копирование;
- не требуется общий доступ нескольких серверов приложения.

Проверьте, что каталоги созданы после выполнения:

```bash
php init --env=Production
```

Пользователь веб-сервера должен иметь права записи в рабочие каталоги, созданные проектом.

!!! warning "Важно"
    Не изменяйте права вручную без необходимости. Стандартные каталоги и права создаются командой инициализации проекта.

## 4. Выбор внешнего хранилища

Портал может использовать:

- AWS S3;
- S3-compatible;
- FTP;
- SFTP;
- WebDAV.

Внешнее хранилище рекомендуется, если:

- используется несколько серверов приложения;
- требуется масштабирование;
- документы должны храниться отдельно от веб-сервера;
- необходимы встроенные механизмы репликации или версионирования.

## 5. AWS S3 и S3-compatible

Для подключения обычно требуются:

| Параметр | Назначение |
|---|---|
| Endpoint | Адрес сервиса |
| Region | Регион |
| Bucket | Имя контейнера |
| Access key | Идентификатор доступа |
| Secret key | Секретный ключ |
| Path style | Режим адресации, если требуется |

!!! danger "Важно"
    Секретные ключи нельзя хранить в публичном репозитории.

Для S3-compatible сервисов дополнительно проверьте:

- совместимость API;
- поддержку подписей;
- корректность endpoint;
- использование HTTPS;
- настройки path-style или virtual-hosted-style.

## 6. FTP

Для подключения требуются:

- адрес сервера;
- порт;
- имя пользователя;
- пароль;
- удаленный каталог;
- активный или пассивный режим.

Обычный FTP передает учетные данные без достаточной защиты. Используйте его только в доверенной сети.

## 7. SFTP

SFTP работает поверх SSH и рекомендуется вместо обычного FTP.

Потребуются:

- адрес сервера;
- порт SSH;
- пользователь;
- пароль или SSH-ключ;
- удаленный каталог.

Предпочтительно использовать отдельного пользователя с доступом только к каталогу хранения.

## 8. WebDAV

Для подключения требуются:

- URL сервера WebDAV;
- имя пользователя;
- пароль;
- корневой каталог;
- действующий HTTPS-сертификат.

Проверьте ограничения размера файлов и время ожидания на стороне WebDAV-сервера.

## 9. Настройка портала

Фактическая конфигурация зависит от используемого адаптера хранения и версии портала.

Настройки размещаются в локальных конфигурационных файлах проекта, обычно в:

```text
common/config/main-local.php
```

Перед изменением сохраните резервную копию файла.

## 10. Проверка

После настройки:

1. Загрузите тестовый файл через портал.
2. Убедитесь, что файл появился в выбранном хранилище.
3. Откройте или скачайте файл через интерфейс портала.
4. Проверьте журналы приложения.
5. Удалите тестовый файл штатными средствами портала.

## 11. Резервное копирование

Локальное хранилище необходимо включить в резервное копирование сервера.

Для внешних хранилищ проверьте:

- версионирование объектов;
- срок хранения удаленных файлов;
- репликацию;
- отдельный доступ к резервным копиям;
- процедуру восстановления.

## 12. Безопасность

Рекомендуется:

- использовать HTTPS, SFTP или защищенный S3 endpoint;
- выдавать минимально необходимые права;
- использовать отдельные учетные записи;
- регулярно менять секретные ключи;
- ограничивать доступ по сети;
- не размещать секреты в Git.

## 13. Типичные ошибки

### Файл загружается, но не открывается

Проверьте:

- корректность пути;
- права доступа;
- URL хранилища;
- доступ веб-сервера к файлу.

### Ошибка авторизации

Проверьте учетные данные, срок действия ключей и разрешения пользователя.

### Ошибка сертификата

Проверьте цепочку SSL-сертификата и системное хранилище доверенных сертификатов.
