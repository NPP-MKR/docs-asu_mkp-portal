# Настройка HTTPS

Версия документа: 1.0

## 1. Назначение

Документ описывает общие требования к HTTPS для портала АСУ МКР.

HTTPS обязателен для:

- Frontend;
- Backend;
- API.

## 2. Предварительные требования

Перед выпуском сертификата:

1. Создайте DNS-записи.
2. Убедитесь, что домены указывают на сервер.
3. Настройте виртуальные хосты.
4. Проверьте доступность сайтов по HTTP.
5. Откройте порты 80 и 443.

## 3. Доменные имена

Пример:

| Компонент | Домен |
|---|---|
| Frontend | `portal.example.com` |
| Backend | `admin.example.com` |
| API | `api.example.com` |

Для каждого имени нужен действующий сертификат.

## 4. Let's Encrypt

Для бесплатных сертификатов рекомендуется Let's Encrypt.

Установите Certbot подходящим для операционной системы способом.

Для Apache обычно используется плагин Apache, для Nginx — плагин Nginx.

После установки выполните выпуск сертификата для каждого домена либо одного сертификата сразу для трех имен.

Пример:

```bash
sudo certbot --apache     -d portal.example.com     -d admin.example.com     -d api.example.com
```

Для Nginx:

```bash
sudo certbot --nginx     -d portal.example.com     -d admin.example.com     -d api.example.com
```

## 5. Коммерческий сертификат

При использовании коммерческого сертификата потребуются:

- файл сертификата;
- приватный ключ;
- промежуточные сертификаты;
- инструкция удостоверяющего центра.

Приватный ключ должен быть доступен только администратору и веб-серверу.

## 6. Перенаправление HTTP на HTTPS

После настройки сертификатов весь HTTP-трафик рекомендуется перенаправлять на HTTPS.

Не отключайте порт 80, если он используется для автоматического продления Let's Encrypt.

## 7. Проверка

Откройте:

```text
https://portal.example.com
https://admin.example.com
https://api.example.com
```

Проверьте:

- отсутствие предупреждений браузера;
- корректность доменного имени;
- срок действия;
- полную цепочку сертификатов;
- перенаправление HTTP на HTTPS.

## 8. Автоматическое продление

Проверьте таймер Certbot:

```bash
systemctl status certbot.timer
```

Выполните тестовое продление:

```bash
sudo certbot renew --dry-run
```

## 9. Безопасность

Рекомендуется:

- использовать современные версии TLS;
- отключить устаревшие протоколы;
- защищать приватные ключи;
- контролировать срок действия сертификатов;
- проверять автоматическое продление.

## 10. Типичные ошибки

### Сертификат выпущен не для того домена

Проверьте `server_name` или `ServerName` виртуального хоста.

### Не удается выпустить сертификат

Проверьте DNS, порты 80/443 и доступность сайта из Интернета.

### Браузер показывает неполную цепочку

Установите промежуточные сертификаты.
