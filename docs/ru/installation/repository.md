# Получение исходного кода

Версия документа: 1.0

## 1. Назначение

Документ описывает:

- выбор версии портала;
- создание отдельного SSH-ключа;
- отправку публичного ключа администратору;
- настройку SSH-подключения к GitHub;
- клонирование репозитория;
- проверку доступа;
- типичные ошибки.

## 2. Выбор версии портала

Доступны две версии портала.

| Версия | Статус |
|---|---|
| **v2** | Актуальная стабильная версия, используемая в эксплуатации |
| **v3** | Новая версия портала, рекомендуемая для новых установок |

### Репозитории

| Версия | Репозиторий |
|---|---|
| v2 | `git@github-mkp:NPP-MKR/mkp-portaloriginal.git` |
| v3 | `git@github-mkp:NPP-MKR/mkp-portaloriginal-v3.git` |

## 3. Создание SSH-ключа

Для доступа к репозиториям рекомендуется создать отдельный ключ с именем `id_mkp`.

На Linux выполните:

```bash
ssh-keygen -t ed25519 -C "your-email@example.com" -f ~/.ssh/id_mkp
```

Во время выполнения команды можно задать пароль для защиты приватного ключа.

После создания будут получены два файла:

| Файл | Назначение |
|---|---|
| `~/.ssh/id_mkp` | Приватный ключ |
| `~/.ssh/id_mkp.pub` | Публичный ключ |

!!! danger "Важно"
    Приватный ключ `id_mkp` нельзя передавать другим лицам или отправлять по электронной почте.

## 4. Отправка публичного ключа

Найдите файл:

```text
~/.ssh/id_mkp.pub
```

Отправьте содержимое файла на электронную почту:

**info@mkr.org.ua**

В письме рекомендуется указать:

- организацию;
- Ф.И.О.;
- должность;
- контактный e-mail;
- проект «АСУ МКР»;
- требуемую версию портала.

!!! warning "Важно"
    Отправляется только публичный ключ `id_mkp.pub`.

После регистрации ключа администратор сообщит о предоставлении доступа.

## 5. Настройка SSH-конфигурации

Откройте или создайте файл:

```text
~/.ssh/config
```

Добавьте конфигурацию:

```text
Host github-mkp
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_mkp
    IdentitiesOnly yes
```

Псевдоним `github-mkp` используется в адресах репозиториев проекта.

## 6. Проверка SSH-подключения

После настройки выполните:

```bash
ssh -T git@github-mkp
```

При первом подключении SSH может запросить подтверждение ключа хоста GitHub. После подтверждения должен появиться ответ об успешной аутентификации.

Если появляется ошибка:

```text
Could not resolve hostname github-mkp
```

значит файл `~/.ssh/config` отсутствует, содержит ошибку или SSH не видит запись `Host github-mkp`.

## 7. Выбор каталога установки

Перед клонированием выберите каталог, в котором будет размещен портал.

Для Linux обычно используется:

```text
/var/www
```

Перейдите в него:

```bash
cd /var/www
```

## 8. Клонирование версии v2

Для установки актуальной стабильной версии выполните:

```bash
git clone git@github-mkp:NPP-MKR/mkp-portaloriginal.git mkp
```

После завершения исходный код будет находиться в каталоге:

```text
/var/www/mkp
```

## 9. Клонирование версии v3

Для установки новой версии портала выполните:

```bash
git clone git@github-mkp:NPP-MKR/mkp-portaloriginal-v3.git mkp
```

После завершения исходный код будет находиться в каталоге:

```text
/var/www/mkp
```

!!! note "Примечание"
    Для новых установок рекомендуется версия v3. Если организация уже использует v2, выбор версии следует согласовать с сопровождающими систему специалистами.

## 10. Переход в каталог портала

После клонирования перейдите в каталог проекта:

```bash
cd /var/www/mkp
```

В дальнейшей документации этот путь обозначается как:

```text
<каталог_портала>
```

## 11. Обновление локальной копии

Для получения последних изменений сначала перейдите в каталог портала:

```bash
cd <каталог_портала>
```

Затем выполните:

```bash
git pull
```

Полный порядок обновления портала приведен в документе [Установка портала](install.md#12-обновление-портала).

## 12. Типичные ошибки

### Permission denied (publickey)

Возможные причины:

- публичный ключ еще не зарегистрирован;
- используется другой SSH-ключ;
- неверно настроен `~/.ssh/config`;
- отсутствуют права доступа к репозиторию.

### Could not resolve hostname github-mkp

Проверьте наличие записи `Host github-mkp` в файле `~/.ssh/config`.

### Repository not found

Проверьте:

- правильность адреса репозитория;
- наличие доступа к выбранной версии;
- успешность SSH-аутентификации.
