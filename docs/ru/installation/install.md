# Установка портала АСУ МКР

Версия документа: 1.0

## 1. Введение

Настоящее руководство описывает установку новой копии портала **АСУ МКР**.

Основной рекомендуемой платформой является Linux. Портал также может быть развернут на сервере под управлением Windows, однако отдельная инструкция по подготовке Windows Server в составе данной документации не предоставляется.

Документ рассчитан в том числе на администраторов без опыта установки портала. Действия приведены в том порядке, в котором их необходимо выполнять.

Подробное описание отдельных этапов вынесено в специализированные документы.

> **Важно**
>
> Не переходите к следующему этапу, пока не завершен и не проверен предыдущий.

## 2. Структура документации

В процессе установки используются следующие документы:

- `server-linux.md` — подготовка сервера под управлением Linux;
- `repository.md` — настройка доступа и получение исходного кода;
- `firebird.md` — установка и настройка Firebird;
- `storage.md` — настройка файлового хранилища;
- `apache.md` — настройка Apache;
- `nginx.md` — настройка Nginx;
- `ssl.md` — настройка HTTPS;
- `Recommendations.md` — рекомендации по эксплуатации портала.

Для Windows Server администратор должен самостоятельно установить и настроить требуемые компоненты в соответствии с системными требованиями.

## 3. Системные требования

### 3.1 Операционная система

Рекомендуемые операционные системы:

| Операционная система | Версия |
|---|---|
| Ubuntu Server | 22.04 LTS и выше |
| Debian | 12 и выше |

Также допускается использование Windows Server при условии, что на сервере установлены и правильно настроены все необходимые компоненты.

### 3.2 Программное обеспечение

| Компонент | Требование |
|---|---|
| PHP | 8.1 и выше, рекомендуется 8.3 |
| Composer | 2.6 и выше |
| Git | актуальная стабильная версия |
| Firebird | 3.0.x |
| Веб-сервер | Apache или Nginx |

### 3.3 Расширения PHP

Должны быть установлены следующие расширения PHP:

- `bcmath`;
- `curl`;
- `dom`;
- `fileinfo`;
- `gd`;
- `gettext`;
- `iconv`;
- `imap`;
- `intl`;
- `mbstring`;
- `openssl`;
- `pdo`;
- `pdo_firebird`;
- `simplexml`;
- `xml`;
- `zip`.

## 4. Подготовка сервера

Установку необходимо выполнять последовательно.

### 4.1 Установка операционной системы

Сначала установите поддерживаемую серверную операционную систему и выполните ее первоначальную настройку.

Для Linux рекомендуется использовать Ubuntu Server 22.04 LTS или Debian 12.

Подробная инструкция для Linux приведена в документе `server-linux.md`.

### 4.2 Установка PHP

После подготовки операционной системы установите PHP требуемой версии и все обязательные расширения из раздела «Системные требования».

После установки проверьте версию PHP:

```bash
php -v
```

### 4.3 Установка Composer

После установки PHP установите Composer.

Проверьте его доступность:

```bash
composer --version
```

### 4.4 Установка Git

Установите Git, который используется для получения и обновления исходного кода портала.

Проверьте его доступность:

```bash
git --version
```

### 4.5 Установка Firebird

Установите Firebird 3.0.x и убедитесь, что служба базы данных запущена.

Подробная настройка приведена в документе `firebird.md`.

### 4.6 Установка веб-сервера

Установите один из поддерживаемых веб-серверов:

- Apache;
- Nginx.

На этом этапе достаточно установить веб-сервер. Виртуальные хосты настраиваются позже, после получения и инициализации проекта.

## 5. Получение исходного кода

После установки всех необходимых компонентов настройте доступ к репозиторию и получите исходный код портала.

Подробная инструкция по созданию SSH-ключа, отправке публичного ключа, выбору версии портала и клонированию репозитория приведена в документе `repository.md`.

Портал можно разместить в любом каталоге, доступном пользователю, от имени которого выполняется установка. В Linux обычно используются:

- `/var/www`;
- `/opt`.

После клонирования запомните полный путь к каталогу проекта.

Например:

```text
/var/www/mkp
```

Во всей документации этот путь обозначается как:

```text
<каталог_портала>
```

## 6. Установка зависимостей

Перейдите в каталог портала:

```bash
cd <каталог_портала>
```

Установите PHP-зависимости проекта без пакетов для разработки:

```bash
composer install --no-dev
```

> **Важно**
>
> Команда должна завершиться без критических ошибок.

## 7. Инициализация проекта

Оставаясь в корневом каталоге портала, выполните инициализацию производственного окружения:

```bash
php init --env=Production
```

Во время инициализации автоматически создаются необходимые локальные конфигурационные файлы, каталоги, ссылки и права доступа.

> **Важно**
>
> Команда `php init --env=Production` выполняется только при первоначальной установке портала. При обычном обновлении повторно запускать ее не требуется.

После завершения инициализации откройте файл:

```text
common/config/main-local.php
```

В этом файле выполняется первоначальная настройка портала.

### 7.1 Права доступа

После инициализации проверьте права доступа к рабочим каталогам и конфигурационным файлам портала.

| Каталог | Назначение |
|---|---|
| `backend/runtime` | runtime backend |
| `backend/web/assets` | assets backend |
| `frontend/runtime` | runtime frontend |
| `frontend/web/assets` | assets frontend |
| `api/runtime` | runtime api |
| `common/config/*-local.php` | настройки портала |
| `common/config` | конфиг-файлы (languages, main, api-*, auth-local) |
| `frontend/config` | конфиг-файлы (serviceManager-local.php) |
| `assets/users` | файлы настроек, logo, тексты на главной, portal.css/js и другие |
| `assets/contract` | файлы шаблонов контрактов и статусов |
| `storage` | файловое хранилище |

> **Права доступа**
>
> - каталоги — `0775`;
> - конфигурационные файлы — `0664`;
> - владелец — пользователь веб-сервера.

## 8. Настройка портала

### 8.1 Настройка баз данных

В файле `common/config/main-local.php` настройте подключения к двум базам Firebird:

| Подключение | Назначение |
|---|---|
| `BD` | Основная база данных АСУ МКР |
| `BDD` | Дополнительная база данных |

Для каждого подключения необходимо указать:

- путь к базе данных;
- имя пользователя;
- пароль;
- при необходимости — адрес сервера Firebird.

Подробная инструкция приведена в документе `firebird.md`.

### 8.2 Настройка файлового хранилища

По умолчанию портал использует локальную файловую систему. Для стандартной установки этот вариант рекомендуется оставить без изменений.

Используются следующие настройки:

| Хранилище | Каталог |
|---|---|
| `fs` | `@webroot/documents` |
| `storage` | `@frontend/web` |

При необходимости портал можно подключить к внешнему хранилищу:

- AWS S3;
- S3-compatible;
- FTP;
- SFTP;
- WebDAV.

Подробная настройка вынесена в документ `storage.md`.

## 9. Настройка веб-сервера

После получения и настройки проекта создайте отдельные виртуальные хосты для трех частей портала.

Для начинающего администратора виртуальный хост можно понимать как отдельное доменное имя или поддомен, направленный на определенный каталог приложения.

Пример:

| Поддомен | Назначение | Корневой каталог |
|---|---|---|
| `portal.example.com` | Пользовательская часть портала | `<каталог_портала>/frontend/web` |
| `admin.example.com` | Административная часть | `<каталог_портала>/backend/web` |
| `api.example.com` | API портала | `<каталог_портала>/api/web` |

Вместо `example.com` необходимо использовать доменное имя организации.

Администратор самостоятельно выбирает Apache или Nginx.

Подробная настройка приведена в документах:

- `apache.md`;
- `nginx.md`.

## 10. Настройка HTTPS

Использование HTTPS обязательно для всех трех виртуальных хостов:

- Frontend;
- Backend;
- API.

Для каждого доменного имени необходимо установить действующий SSL-сертификат.

Можно использовать:

- бесплатный сертификат Let's Encrypt;
- сертификат коммерческого удостоверяющего центра.

HTTP рекомендуется использовать только для автоматического перенаправления пользователей на HTTPS.

Подробная инструкция приведена в документе `ssl.md`.

## 11. Первый запуск

После завершения настройки откройте в браузере адрес пользовательской части портала, например:

```text
https://portal.example.com
```

Затем откройте административную часть:

```text
https://admin.example.com
```

После этого проверьте адрес API:

```text
https://api.example.com
```

Убедитесь, что:

- страницы открываются по HTTPS;
- отсутствуют ошибки веб-сервера;
- портал подключается к базам `BD` и `BDD`;
- в журналах приложения отсутствуют критические ошибки.

## 12. Обновление портала

Перед обновлением рекомендуется создать резервные копии:

- баз данных;
- файла `common/config/main-local.php`;
- пользовательских документов;
- файлового хранилища.

Затем перейдите в каталог портала:

```bash
cd <каталог_портала>
```

Получите изменения из репозитория:

```bash
git pull
```

Обновите PHP-зависимости проекта без пакетов для разработки:

```bash
composer update --no-dev
```

После обновления зависимостей очистите кэш приложения:

```bash
php yii cache/flush-all
```

> **Важно**
>
> Команду `php init --env=Production` при обновлении запускать не нужно.

После завершения обновления рекомендуется очистить кэш браузера и повторно проверить Frontend, Backend и API.
