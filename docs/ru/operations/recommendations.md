# Рекомендации по эксплуатации

Версия документа: 1.0

## 1. Назначение

Документ содержит рекомендации по безопасной и стабильной эксплуатации портала АСУ МКР.

## 2. Обновление

Перед обновлением:

1. Создайте резервные копии.
2. Проверьте свободное место.
3. Ознакомьтесь с изменениями.
4. Выполняйте обновление в согласованное время.
5. После обновления проверьте Frontend, Backend и API.

Порядок команд приведен в документе [Установка портала](../installation/install.md#12-обновление-портала).

## 3. Резервное копирование

В резервное копирование включите:

- базы `BD` и `BDD`;
- `common/config/main-local.php`;
- локальное файловое хранилище;
- пользовательские документы;
- конфигурации Apache или Nginx;
- SSL-сертификаты и приватные ключи.

Резервные копии должны храниться отдельно от рабочего сервера.

## 4. Проверка восстановления

Создание резервной копии не гарантирует возможность восстановления.

Регулярно выполняйте тестовое восстановление:

- базы данных;
- файлов;
- конфигурации;
- полного сервера при наличии образов.

## 5. Мониторинг

Контролируйте:

- доступность Frontend, Backend и API;
- загрузку CPU;
- использование RAM;
- свободное место;
- состояние Firebird;
- состояние PHP-FPM;
- состояние Apache или Nginx;
- срок действия SSL-сертификатов;
- ошибки приложения.

## 6. Журналы

Регулярно проверяйте:

- журналы приложения;
- журналы веб-сервера;
- журналы PHP;
- системный журнал;
- журналы Firebird.

Настройте ротацию журналов, чтобы они не заполнили диск.

## 7. Безопасность

Рекомендуется:

- устанавливать обновления ОС;
- использовать сложные уникальные пароли;
- ограничивать SSH-доступ;
- использовать ключи вместо паролей;
- ограничивать доступ к Firebird;
- использовать HTTPS;
- не хранить секреты в Git;
- выдавать минимально необходимые права;
- удалять доступ уволенных сотрудников.

## 8. Производительность

При росте нагрузки контролируйте:

- использование памяти PHP;
- количество процессов PHP-FPM;
- медленные запросы;
- размер журналов;
- нагрузку на Firebird;
- скорость файлового хранилища;
- время ответа API.

Изменения производительности сначала проверяйте на тестовом окружении.

## 9. Тестовое окружение

Для обновлений и изменений рекомендуется отдельное тестовое окружение.

Оно должно по возможности повторять:

- версию ОС;
- версию PHP;
- версию Firebird;
- конфигурацию веб-сервера;
- настройки файлового хранилища.

## 10. Документирование изменений

Фиксируйте:

- дату обновления;
- установленную версию;
- выполненные команды;
- измененные конфигурации;
- результат проверки;
- обнаруженные проблемы.
